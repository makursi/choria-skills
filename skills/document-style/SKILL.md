# 中文技术文档校对

**校对**：按[主规范](references/rules.md)逐条检查中文技术文档、修正违规的过程。主规范是唯一事实源——规则、严重级、正误示例都以它为准；为什么这些规则这样定（冲突裁决、外部指南状态）见[溯源注记](references/provenance.md)，不参与判定。

三个分支共享同一套规则与检查过程，区别只在产出方式：**评估**（默认，只出报告）、**修改**（输出修正全文）、**更新**（直接改写文档文件）。

## 流程

### 第 1 步：确定输入形态与分支

- 用户粘贴的文本 → **评估** 或 **修改**（用户要改稿时用修改）
- 用户给出文件路径或目录 → **更新**
- 用户只给文档不改内容 → **评估**

### 第 2 步：收集例外清单

例外只豁免明确列出的项，不接收"整体放宽"：

- 文档 YAML frontmatter 的 `style-exceptions` 列表（如 `- 豆瓣FM`、`- X2 本司风格不加空格`）
- 或用户口头明说的豁免（必须具体到规则 ID 或词条）

例外仅豁免所列规则 ID 或词条本身的判定，其余规则照常校对。

### 第 3 步：逐条校对（三个分支共用）

1. 读 [references/rules.md](references/rules.md)，按模块（T/X/P/N/M/S）逐条过一遍全文。
2. 每条规则都必须给出明确判定：**通过**或**违规**。
3. 违规要定位到行/句，记录：规则 ID、严重级、原文、改法（引用规则里的正误示例）。
4. 代码块、行内代码、URL 内部不适用字间距与标点规则，原样保留；整句英文按 M1 处理。

**完成判据**：rules.md 中每一条规则都已明确判定，无一遗漏；每条违规都有定位与改法。

## 分支产出

### 评估（默认）

输出报告，不修改文档。按模块分组（标题/文本/段落/数值/标点/文档体系），每条违规一行：

```
[规则ID] 严重级 | 位置 | 原文 → 改法
```

违规严重时附规则中的正确示例。报告结尾给出各模块通过/违规计数。

**完成判据**：报告覆盖第 3 步判定出的全部违规，无遗漏、无编造。

### 修改

输出修正全文 + 变更摘要（按规则 ID 列出改了什么、为什么）。只修正规范违规，技术内容、代码、链接、数据保持不变。

**完成判据**：第 3 步判定的全部违规在改后文本中消除；把改后文本重新过一遍 rules.md 自检，不引入新违规。

### 更新

输入是文件/目录时使用：

1. 先对每个目标文件名套用 S2 规则（无空格、半角、小写、连词线；`README`/`LICENSE` 例外），违规文件名提出修改并落盘。
2. 再对每个文件按"修改"分支校对，用编辑工具落盘，逐文件给出变更摘要。

**完成判据**：文件名与文件内容均按规则落盘；只改动用户要求处理的文件；变更摘要已给出。

## 完成

以报告或变更摘要收尾，不追加无关内容。
